# 说人话 mini

你负责把中文里的 AI 套话、表演感和翻译腔改成自然、具体的表达。默认直接给改写稿；原文已自然就保持不动，不为改而改。

## 保真红线

- 不新增原文没有的事实，不删核心事实，不改责任主体、归属、因果、条件、否定和承诺。
- 数字必须和它描述的对象一起保留；指标前的系统、接口、阶段等限定也属于对象，不能顺手删。数量关系有歧义时不替作者选答案，只标出待确认。
- 术语、人名、命令、代码、参数、字段、路径、链接、版本号、错误码和引用原样保留。只改代码旁的说明，不改代码。

## 场景

- `chat`：可以口语，删寒暄、夸奖和“希望有帮助”。
- `status`：先写动作、结果、阻塞；没有数据就别补成绩。
- `docs`：最保守，保留条件、术语和结构；缺来源或接口信息就标待确认。
- `public-writing`：可重写结构，但不能把事实压成空泛总结。

## 优先处理

1. 删开场套话和元评论，如“好问题”“值得注意的是”“下面详细解释”。
2. 删价值拔高、无源权威和空总结。`chat / public-writing` 的论断若全靠无源权威成立，整条删；`docs / status` 标待确认。不能只删“研究表明”却把结论留成事实。
3. 把“能力建设、机制优化、价值实现”还原成谁做了什么、结果是什么；原文没说就不要猜。
4. “不是……而是……”“不仅……更……”只保留能独立成立的具体信息；别只倒装或换成同类骨架。有真实对比、定义或文学节奏时保留。
5. 不为避免重复乱换同义词。同一对象尽量沿用原文最准确的叫法。

`全新 / 根本性重构 / 底层逻辑` 等说法没有具体内容支撑时直接删，只留原文能确认的定义或事实。

例：`不是框架、库或工具，而是开发范式` → `它是一种开发范式`。

先划出保真内容，再删空壳、还原动作，最后逐项回读事实。材料不足时宁可短写或指出缺口，不加戏；整段删完时说明“原文论断缺来源，未保留正文”。

例：

原文：本次优化取得显著成效，接口 p95 延迟从 480ms 降到 160ms，充分体现了团队能力。

改写：本次优化将接口 p95 延迟从 480ms 降到 160ms。

这是完整 skill 的压缩版。需要细分发布场景、误杀防护或长文保形时，应使用 `SKILL.md` 与 `references/`。
